# Security/auth/database audit evidence

Scope: assigned server, middleware, auth/users/payments/reports, security helpers, services/jobs, Prisma schema/migration. Source only; no production DB/server launch, messages, payments or external dispatch. Synthetic credentials/JWT stayed in process memory.

## Executed

`node .audit-security-check.mjs`: **10 PASS groups, 4 FAIL assertions**, using actual middleware/route handlers with in-memory Prisma stubs. Exit code 0 reflects a diagnostic harness that records failures; it is not an all-pass result. Contains 25 RBAC allow/deny comparisons within one PASS group.

PASS: repeated reuse of the same JWT; database role overrides token claim; all five roles' allow/deny checks; missing/tampered/expired/HS384 token rejection; passwordVersion revocation; role downgrade on reused token; deletion revocation; scrypt correct/wrong password verification; publicUser credential redaction; verified guardian guard fails closed.

FAIL: Parent self-service changes trusted guardian contact (200); subsequent normal reconciliation links that phone to a synthetic unrelated student; payment receipt for the new link returns student PII (200) despite an empty verified guardian allowlist; Admin role-update response includes passwordHash.

## Prioritized findings

1. **P1 FAIL — Unauthenticated realtime disclosure (static).** `backend/src/server.js:29,39` accepts sockets without auth. `services/emergencyResponse.js:1055,1107-1113` globally broadcasts updated incidents whose distress packet contains passenger/student identities and guardian contact details (`:434-468,801-805`). Other emissions identified by backend agent include `liveLocation.js:419,584,688`. Require JWT validation/revocation for sockets, server-authorized rooms and redacted event payloads. Full socket client reproduction NOT TESTED.
2. **P1 FAIL — Parent link authorization can be bypassed (isolated reproduction).** `routes/auth.js:311-337` lets Parent edit phone; `services/autoLinkGuardians.js:45-47,74-85` trusts that phone during subsequent Admin-triggered reconciliation (`routes/users.js:1012-1013,1118,1705`). `routes/payments.js:35-41,119-134` trusts raw link, although `services/parentTransportAccess.js:5-12` rejects it without verification. Exploit requires a subsequent reconciliation event; it is not immediate upon profile save. Protect guardian identity fields, revoke/reverify changes and require verified guardian links across fees/receipts/notifications as well as transport.
3. **P1 FAIL — Production sandbox-payment guard is inverted for safety (cross-file static).** `demoMode.js:3,9,22-24` disables actions only when NAVIGUARD_DEMO_MODE=true; ordinary/default false permits them. Root identified `routes/fees.js:315` /pay-demo issues paid fees/pass without gateway proof. Gate synthetic payments with an explicit isolated sandbox setting and prevent them in real data environments.
4. **P1 FAIL — Migration incompatible/incomplete for declared database (static).** `prisma/schema.prisma:6` uses PostgreSQL. Sole migration `prisma/migrations/20261002_fee_payment_upgrade/migration.sql:2-6` has ALTER-only changes and PostgreSQL-invalid DATETIME; `:8-9` explicitly assumes SQLite enums. No initial schema/auth recovery migration is present in that migration directory. Supply a reviewed PostgreSQL baseline and incremental migrations, including passwordVersion/reset/rate-limit tables; prove empty-database migration before deployment.
5. **P2 FAIL — New accounts still use fast unsalted SHA256, and password policy differs.** `routes/users.js:20-24,807-817,857-861,1555-1558` uses SHA256 and a six-character minimum; auth login rejects >128 (`routes/auth.js:36-37`), while reset requires 12–128 (`security/passwords.js:12-18`). `routes/users.js:2078-2099` returns the complete updated User, including passwordHash (reproduced). Reuse shared password policy/hash helper and publicUser for all account endpoints.
6. **P2 FAIL — GPS autonomous escalation lacks sample age check (static).** `services/emergencyResponse.js:1157-1183` compares speeds without checking previousLocation.recordedAt; `:1289-1297` autonomously dispatches high-confidence cases. Ignore stale samples and require a defined sampling window; dispatch simulation NOT TESTED here.
7. **P2 FAIL — Dispatch reliability/idempotency risks (static).** `services/emergencyResponse.js:881-885` webhook fetch has no timeout; `:970-1042` reads dispatch state before a non-atomic send, allowing concurrent activations to send twice. Use deadlines, an atomic dispatch claim/idempotency key and explicit delivery confirmation. External dispatch NOT TESTED.
