1. **FAIL P1 — Driver can raise/escalate incidents for another bus.** `backend/src/routes/incidents.js:381` SOS trusts `vehicleId`; `:448` accident detection only checks bus existence (`:470`) before creating the incident (`:529`) and requesting autonomous response (`:615`). Require current driver/active-bus assignment and coordinate/sensor bounds; derive bus server-side. Evidence `.audit-backend-probes.log`.
2. **FAIL P2 — Concurrent GPS duplicate acceptance.** `backend/src/routes/liveLocation.js:1103` checks timestamp before awaiting transaction; `:1127` updates in-memory watermark afterward. Isolated parallel requests with identical GPS timestamp returned **200,200** and two mocked location writes; sequential duplicate returned **400**. Enforce atomic per-bus ordering/deduplication and store a durable timestamp. Probe has no network/real persistence.
3. **FAIL P2 — GET live tracking has write side effects.** `liveLocation.js:818`, `:824`, `:828` invoke notification writers for deviation/speed/staleness. A nominally read-only audit or polling can create notifications; production GET intentionally not executed. Move side effects into update/background processing with durable deduplication.

Confirm intended Staff journey and align endpoints/UI.

Multi-worker consistency and restart recovery are absent. Persist/coordinate sessions before production scale-out.
